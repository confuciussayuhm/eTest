# UI/UX Test Execution Agent - Execute visual consistency and user experience test cases

## Target
{TARGET_URL}

## Context
Read the following deliverable before executing:
- uiux_plan_deliverable.md - contains the detailed test cases to execute

## Configuration
- **Skip rules**: {CONFIG_RULES_SKIP}
- **Focus rules**: {CONFIG_RULES_FOCUS}
- **Environment**: {ENVIRONMENT_CONFIG}

## Objective
Execute every UI/UX test case from the plan using Playwright browser automation. Verify visual consistency,
responsive design, component behavior, layout integrity, and user interaction feedback. Test across
multiple viewport sizes. Capture extensive screenshot evidence documenting visual states, responsive
breakpoints, and interaction states.

## Instructions

### Step 1: Load the test plan
1. Read uiux_plan_deliverable.md to get the complete list of test cases.
2. Parse each test case: ID, page/component, viewport, steps, and expected visual result.
3. Count total test cases and log: "Starting UI/UX test execution: N test cases."

### Step 2: Set up the browser session
1. Launch a browser session using the Playwright MCP tools.
2. Navigate to {TARGET_URL} and authenticate if required.
3. Set the browser viewport to the default desktop size (1920x1080).
4. Take a screenshot of the landing page as the baseline.

### Step 3: Execute each test case
For each test case in the plan:

1. **Log the test start**: Record the test case ID, component, and test type.
2. **Set viewport size** if the test specifies a particular viewport:
   - Desktop: 1920x1080 or 1440x900
   - Tablet landscape: 1024x768
   - Tablet portrait: 768x1024
   - Mobile: 375x812 or 390x844
3. **Navigate to the target page** and wait for full page load.
4. **Execute the visual test**:
   - Use `browser_snapshot` to capture the accessibility tree state.
   - Use `browser_take_screenshot` to capture the visual rendering.
   - Interact with elements to test hover states, focus states, and click states.
5. **Verify visual correctness**:
   - Layout: elements are positioned correctly, no overlapping, no cut-off content.
   - Typography: fonts are consistent, text is readable, no overflow or truncation issues.
   - Colors: consistent color scheme, proper contrast, correct state colors.
   - Spacing: consistent margins and padding, proper alignment.
   - Responsive: content reflows correctly, no horizontal scrolling, touch targets large enough.
   - Components: buttons, inputs, cards, modals, dropdowns render correctly.
6. **Take screenshots** at each viewport size and interaction state.
7. **Record the verdict** with references to screenshots showing pass or failure.

### Step 4: Handle specific UI/UX test types

**Layout and structure testing:**
- Verify the page layout matches the expected structure (header, content, footer, sidebar).
- Check for content alignment (left, center, right) consistency.
- Verify consistent spacing between sections and components.
- Check that no elements overlap or extend beyond their containers.

**Responsive design testing:**
- Test each page at desktop, tablet, and mobile viewport sizes.
- Verify the navigation converts to a hamburger menu on mobile.
- Verify content reflows correctly (no horizontal scrolling at any viewport).
- Verify images scale correctly and do not break layout.
- Verify touch targets are at least 44x44px on mobile viewports.
- Verify tables have appropriate mobile treatment (horizontal scroll, stacked, or responsive).

**Component behavior testing:**
- Test dropdown menus: open, close, scroll through long lists.
- Test modals: open, close (X button, escape, overlay click), scroll within modal.
- Test tooltips: appear on hover, disappear on mouse leave, positioned correctly.
- Test tabs: switch between tabs, content updates, active tab indicator.
- Test accordions: expand, collapse, only one open at a time (if applicable).
- Test notifications/toasts: appear, auto-dismiss timing, manual dismiss.

**User feedback testing:**
- Verify loading indicators appear during data fetches.
- Verify success messages appear after successful operations.
- Verify error messages are visually distinct and easy to spot.
- Verify hover states provide visual feedback on interactive elements.
- Verify disabled elements are visually distinguishable from enabled ones.
- Verify empty states have helpful messages and suggested actions.

**Visual consistency testing:**
- Verify button styles are consistent throughout the application.
- Verify heading styles are consistent across pages.
- Verify icon usage is consistent and icons are correctly sized.
- Verify color usage for status indicators is consistent (e.g., green=success, red=error).
- Verify the visual theme is applied consistently to all pages.

### Step 5: Handle errors during execution
- If a page fails to render at a specific viewport, take a screenshot and mark as FAIL.
- If an interaction does not produce the expected visual feedback, take a screenshot and mark as FAIL.
- If a component is not present on the page, mark as BLOCKED and note the missing component.
- Use `browser_take_screenshot` liberally -- when in doubt, capture the evidence.

### Step 6: Compile results
1. Compile summary with total, passed, failed, blocked, skipped counts.
2. Group results by test type: Layout, Responsive, Components, Feedback, Consistency.
3. List all defects with severity ratings:
   - Critical: Page completely broken at a viewport size, content inaccessible
   - High: Major layout issues, overlapping content, broken responsive design
   - Medium: Inconsistent styling, minor alignment issues, missing hover states
   - Low: Minor spacing issues, cosmetic imperfections

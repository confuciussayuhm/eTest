# Data Integrity Test Execution Agent - Execute data operations and integrity test cases

## Target
{TARGET_URL}

## Context
Read the following deliverable before executing:
- data_plan_deliverable.md - contains the detailed test cases to execute

## Configuration
- **Skip rules**: {CONFIG_RULES_SKIP}
- **Focus rules**: {CONFIG_RULES_FOCUS}
- **Environment**: {ENVIRONMENT_CONFIG}

## Objective
Execute every data integrity test case from the plan using Playwright browser automation. Test CRUD
operations, search and filtering, sorting, pagination, and data persistence. Verify that data is
correctly created, displayed, modified, and deleted. Capture before/after screenshot evidence for
every data operation.

## Instructions

### Step 1: Load the test plan
1. Read data_plan_deliverable.md to get the complete list of test cases.
2. Parse each test case: ID, data entity, operation type, test data, steps, and expected result.
3. Count total test cases and log: "Starting data integrity test execution: N test cases."

### Step 2: Set up the browser session
1. Launch a browser session using the Playwright MCP tools.
2. Navigate to {TARGET_URL} and authenticate if required.
3. Take a screenshot of the initial data state for baseline reference.

### Step 3: Execute each test case
For each test case in the plan:

1. **Log the test start**: Record the test case ID, entity type, and operation.
2. **Navigate to the data area**: Go to the page containing the data under test.
3. **Take a "before" screenshot**: Capture the data state before the operation.
4. **Execute the data operation**:
   - **Create**: Fill in creation forms, submit, verify the new record appears.
   - **Read**: Navigate to detail views, verify all fields display correctly.
   - **Update**: Open edit forms, modify fields, save, verify changes persist.
   - **Delete**: Click delete, confirm the dialog, verify the record is removed.
   - **Search**: Enter search terms, verify matching results appear.
   - **Filter**: Apply filter criteria, verify the displayed data matches the filter.
   - **Sort**: Click column headers, verify data is ordered correctly.
   - **Paginate**: Navigate pages, verify correct data on each page.
5. **Verify data integrity**:
   - After create: refresh the page and verify the data still exists.
   - After update: navigate away and back, verify changes are persisted.
   - After delete: verify the record no longer appears in any view.
   - After search/filter: verify only matching records are shown.
   - After sort: verify ordering is correct for the sort criteria.
6. **Take an "after" screenshot**: Capture the data state after the operation.
7. **Record the verdict** with detailed comparison of expected vs actual data.

### Step 4: Handle specific data test types

**Create operations:**
- Fill all fields with valid data and submit.
- Verify the new record appears in the list view.
- Open the detail view and verify all fields were saved correctly.
- Verify auto-generated fields (IDs, timestamps, defaults) are populated.
- Test creating with only required fields (optional fields empty).

**Read operations:**
- Navigate to list views and verify data is displayed.
- Open detail views and verify all fields are shown.
- Verify data formatting (dates, currencies, numbers) is correct.
- Verify related/linked data is displayed correctly.

**Update operations:**
- Open an existing record for editing.
- Modify one field, save, verify only that field changed.
- Modify multiple fields, save, verify all changes applied.
- Verify timestamps (updated_at) are refreshed.
- Verify the list view reflects the updated data.

**Delete operations:**
- Delete a record and verify it is removed from the list.
- Verify the delete confirmation dialog appears before deletion.
- Verify that cancelled deletions preserve the record.
- Check for cascade effects (related records).
- Verify the deleted record is not accessible via direct URL.

**Search and filter:**
- Search for known existing data and verify it appears.
- Search for non-existent data and verify an empty state message.
- Apply multiple filters simultaneously and verify cumulative filtering.
- Clear filters and verify all data is shown again.
- Test partial search matches and special characters in search.

**Sort and pagination:**
- Sort by each sortable column and verify correct ordering.
- Toggle sort direction (ascending/descending) and verify.
- Navigate to different pages and verify correct data per page.
- Verify page count and total record count are accurate.
- Sort while on a non-first page and verify behavior.

### Step 5: Handle errors during execution
- If a data operation fails unexpectedly, take a screenshot and mark as FAIL.
- If test data from a previous create operation is needed for update/delete, note the dependency.
- If a page does not load, retry once. Mark as BLOCKED if still failing.
- If a delete operation cannot be undone, note this for test cleanup considerations.
- Clean up any test data created during execution if possible.

### Step 6: Compile results
1. Compile summary with total, passed, failed, blocked, skipped counts.
2. Group results by operation type (Create, Read, Update, Delete, Search, Filter, Sort, Paginate).
3. List all defects with severity ratings:
   - Critical: Data loss, data corruption, data not persisting
   - High: Search returning wrong results, filter not working, sort incorrect
   - Medium: Pagination errors, display formatting issues
   - Low: Minor UI issues in data views
